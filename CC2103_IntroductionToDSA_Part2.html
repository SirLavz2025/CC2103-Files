Module 1: What is an Algorithm?

An algorithm is a step-by-step set of instructions designed to solve a specific problem or perform a computation.

📋 Clear & Unambiguous

Every single step must be precisely defined with zero room for misinterpretation.

🛑 Finiteness

An algorithm must always terminate or halt after a finite number of steps.

🎯 Inputs & Outputs

It takes zero or more explicit inputs and guarantees at least one valid output.

Module 2: Why Do We Analyze Algorithms?

Performance matters. Writing code that works is only the first step; making it scalable is what separates good engineers.

⏱️ Time Complexity

Measures how execution time increases as the size of the input data, represented as n, grows larger.

💾 Space Complexity

Measures how much extra memory or RAM space the algorithm demands as input scales.

Module 3: Algorithm Analysis Types

The running time of code often changes depending on how the data is arranged. We classify performance into three core pillars:

🟢 Best-Case (Ω)

The minimum possible time an algorithm takes. E.g., finding your target item on the very first try.

🟡 Average-Case (Θ)

The expected behavior over random inputs. On average, we search halfway through the dataset.

🔴 Worst-Case (O)

The maximum upper bound. Murphy's Law: The item is at the very end or missing entirely.

Module 5: Asymptotic Analysis & Big O

Evaluating performance independent of hardware variations using asymptotic bounds.

Rule 1: Drop Constants

If an algorithm takes 3n steps, drop the constant multiplier 3, leaving O(n).

Rule 2: Keep Dominant Terms

Given n2 + 5n + 10, n2 grows fastest. Lower terms are dropped, resulting in O(n2).
